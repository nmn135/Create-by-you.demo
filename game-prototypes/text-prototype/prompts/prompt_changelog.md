### 一、意图解析 Prompt 修改

#### 新增内容

| 特性 | 理由 | 预期效果 |
|------|------|---------|
| **urgency 字段（1-5）** | 原 prompt 无法区分"随口一问"和"施压逼问"。状态机需要知道玩家追问的强度来判断是否加速失言概率累积。 | `probe_conflict` 时可以根据 urgency 调节失言判定参数；高 urgency 的追问应该更快触发防线崩塌。 |
| **边界情况：空话/无意义输入** | 玩家输入空字符串、"嗯"、"哦"等时，原 prompt 可能随机匹配到某个意图。 | 明确 fallback 到 `stay_silent`，confidence 0.95，避免误分类。 |
| **边界情况：转移话题** | 玩家突然说"天气不错"等无关内容，原 prompt 可能过度解读。 | 降级为 `ask_backstory`，confidence 0.4，等待玩家后续明确。 |
| **边界情况：模糊表达** | "所以……""那个……"等不完整句子，中文对话中极常见。 | 优先从上下文推断话题连续性；无上下文时安全降级。 |
| **漏检保护：过于笼统** | "你觉得呢？""你怎么看？"本身没有指向任何 NPC 或话题。 | 强制 fallback 到 `ask_backstory`，不强行匹配。防止 AI 幻觉出不存在的话题。 |
| **上下文感知（5 轮历史）** | 原 prompt 只接收一句 `context` 字符串，没有结构化历史信息。连续对话中话题可能自然延续，需要让意图解析器知道"刚才在聊什么"。 | 同一话题连续出现 3 次以上 → urgency +1；突然切换话题 → 识别为可能的故意转移。 |
| **中文反问句识别** | "你难道不知道吗？"字面上是 ask，实际是 accuse。原 prompt 没有处理中文反问句。 | 反问句自动识别为 accusatory 语气，urgency +1。 |
| **中文反话/阴阳怪气识别** | "您可真是个大好人啊"——中文玩家可能会用反话表达不满。 | 反话识别为 insinuating 语气，risk_level 适当上调。 |
| **中文委婉表达识别** | "不知道合不合适问……"——玩家知道问题敏感但还是要问。 | 识别为 probe_conflict 或 testing_reaction，比直接追问更精细。 |
| **省略主语暗示** | "那边那位……"——中文口语中省略主语极常见。 | 结合上下文推断省略的 NPC，填充 involves 字段。 |
| **reasoning 字段** | 方便调试——知道 AI 为什么做出某个分类。 | 出问题时可以快速定位是 prompt 理解问题还是上下文缺失。 |

#### 修改内容
- `confidence` 判定标准更透明：< 0.5 时调用方考虑 fallback
- `risk_level` 判定不再只依赖 intent 类型，同时参考措辞攻击性和 urgency
- `urgency` 默认值为 2（正常询问），避免过度敏感或过度迟钝
- 语气类型从 7 种精简为 7 种（保持不变），但每种增加了典型中文特征
- 意图类型从 10 种保持不变，但每种增加了中文触发词和典型模式

### 二、回复生成 Prompt 修改

#### 新增内容

| 特性 | 理由 | 预期效果 |
|------|------|---------|
| **细粒度情绪→微反应映射** | 原 prompt 只有一句"紧张的语言变得简短直接"，太笼统。每个 NPC 有不同性格，同样的"angry"在矮人和精灵身上表现完全不同。 | NPC 的肢体语言和措辞与情绪更匹配；不同 NPC 在同一情绪下有差异化表现。 |
| **对话记忆引用机制** | 原 prompt 中 NPC 没有"记忆"——每轮对话都像第一次见面。真人对话会自然引用之前聊过的内容。 | NPC 偶尔提及之前的对话，增加沉浸感——让玩家感觉 NPC"记得他"。 |
| **失言后的行为逻辑（三模式）** | 原 prompt 只说了"① 试图收回 ② 沉默 ③ 破罐破摔"但没有给具体的行为指导。AI 可能随机选一种，不匹配 NPC 性格。 | 三种模式各有语言特征和适用条件——防御等级、情绪、在场人数都会影响选择。 |
| **在场感知** | 原 prompt 中 NPC 只对玩家说话，完全忽略其他在场 NPC。但公开对话中，所有 NPC 互相能看到反应。 | 非悄悄话模式下，NPC 会注意到其他 NPC 的反应——增强戏剧张力和场景真实感。 |
| **情绪潜台词** | 每种情绪增加"潜台词"维度——让 AI 理解 NPC 的表面行为和内心活动。 | 回复不再只是表面文字，而是有"口是心非""欲言又止"的层次感。 |
| **模板变量完整标注** | 原 prompt 用 Python f-string 直接拼接，没有文档说明哪些是变量。 | 方便后续维护和修改——知道每个 {} 的含义和作用域。 |

#### 修改内容
- calm 增加：正常语速、中等句子长度、潜台词"有防备但愿意交流"
- tense 增加：略快语速、可能半句话就停、潜台词"在衡量风险"
- angry 增加：越愤怒越安静的抑制性描写、下颌线绷紧、手按武器但不拔
- vulnerable 增加：不完整句子、自我打断、眼眶泛红但不会哭——克制比爆发更有力
- hopeful 增加：肩膀不再紧绷、眼中的戒备少了、"也许这一次不一样"

### 三、代码改动（ai_pipeline.py）

#### 动态温度控制

**改动前：** `generate_npc_reply()` 固定 temperature=0.8

**改动后：** 根据 NPC 当前情绪动态选择 temperature：

| 情绪 | 温度 | 理由 |
|------|------|------|
| calm | 0.7 | 平静时语言稳定可预测——比默认 0.8 更低，减少"过度活跃" |
| tense | 0.6 | 紧张时措辞谨慎，不宜太随机 |
| angry | 0.9 | 愤怒时语言更不可预测——更高温度带来更多"失言"和情绪爆发 |
| vulnerable | 0.85 | 脆弱时防御松动，话可能出人意料——比 angry 稍低因为有自控 |
| hopeful | 0.8 | 希望状态下语言自然流畅，不需要太多随机性 |

**理由：** 固定温度导致所有情绪下的语言多样性相同——这与角色状态不一致。愤怒时的语言应该比平静时更不可预测。

#### urgency 字段验证

在 `_validate_intent()` 中添加 `urgency` 字段的校验：
- 合法范围 1-5
- 默认值 2（正常询问）
- 超出范围自动 clamp 到 1 或 5
